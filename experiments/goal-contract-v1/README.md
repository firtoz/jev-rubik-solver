# Consistent goal definitions

The previous full integration used a goal reference allowing direct cross solving with a controller that could only transfer petals. All four runs eventually abstained. This study replaces that conflicting reference, keeping all eight choices available.

Each set contains four mechanically labelled states for each goal. Validation excludes development. Fixtures are constructed from fixed routines, not a representative sample of full random scrambles. Previous-goal and recent-action fields are deliberately controlled synthetic context, not the fixture's scramble history. Labels never enter requests.

One call per state/form, no retries. 96 calls total, $0.004290888. Both development forms use identical teaching and options; compact was selected for fewer tokens after an accuracy tie. This does not isolate individual wording changes or prove repeated-call reliability.

Exact request/native response records are in phase results and the request-flow viewer. The fixture generator and source snapshots support reproduction. Phase markers prevent accidental paid reruns. Local mechanics tests: `bun test tests/goal-contract.test.ts`.
